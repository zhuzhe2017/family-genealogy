# 家谱树性能测试报告

> 测试对象：`mini-program/pages/family-tree-detail` 家谱树绘制核心算法
> 基准脚本：`preview/perf-tree.js`（Node 无依赖自包含，复刻小程序端同款算法）

## 一、测试环境

- 运行环境：Node.js（脚本仅测纯计算复杂度，不依赖 wx / canvas）
- 测试方法：每种规模重复 20 次取中位数，避免抖动
- 数据模型：单根合成家谱，每节点 2~4 个子女，代数随深度递增
- 关键常量（与小程序端一致）：`NODE_W=120`、`NODE_H=76`、`LEVEL_H=180`、`NODE_GAP_X=32`、`PADDING=24`

## 二、测试指标定义

| 指标 | 说明 |
| --- | --- |
| 构建耗时 | 建立 id 映射与父子关系、统计后代数 |
| 布局耗时 | 后序遍历 + 子树居中 + 左边界右移修正，生成各节点坐标 |
| 索引耗时 | 构建空间索引（代际分层 + 代内 x 升序） |
| 每帧遍历次数 | 优化前：getBounds O(n) + 连线/节点两次全量遍历；优化后：缓存 O(1) + 视口裁剪 |

## 三、测试结果

### 3.1 计算耗时（单位：ms）

| 规模 | 构建(ms) | 布局(ms) | 索引(ms) |
| --- | --- | --- | --- |
| 100 | 0.15 | 0.16 | 0.03 |
| 500 | 0.31 | 1.23 | 0.08 |
| 1000 | 0.42 | 0.98 | 0.12 |
| 2000 | 0.80 | 2.38 | 0.21 |
| 5000 | 2.40 | 6.03 | 0.56 |

> 空间索引构建耗时可忽略（5000 人仅 0.56ms），且只在布局变化时执行一次，不计入每帧开销。

### 3.2 每帧遍历次数对比

模拟一个覆盖树中部约 40% 宽度、跨 3 个代际的视口：

| 规模 | 优化前每帧遍历 | 优化后每帧遍历 | 每帧降幅 |
| --- | --- | --- | --- |
| 100 | 300 | 29 | 90.3% |
| 500 | 1500 | 167 | 88.9% |
| 1000 | 3000 | 330 | 89.0% |
| 2000 | 6000 | 575 | 90.4% |
| 5000 | 15000 | 1151 | 92.3% |

### 3.3 渲染速度（推导）

每帧遍历次数与渲染耗时近似线性相关。以 1000 人为例：

- 优化前：每帧约 3000 次节点/连线处理 + getBounds 1000 次扫描。
- 优化后：每帧约 330 次视口内节点处理，getBounds 命中缓存 O(1)。

单帧计算量下降约 89%，在真机 60fps 目标下，从「千人大族明显掉帧」提升到「视口内仅几十个节点，可稳定绘制」。

### 3.4 内存占用（推导）

- **布局/索引结构**：每个节点新增一条 layout 与一条索引引用，均为轻量对象；5000 人额外内存约几十 KB 级，可忽略。
- **缓存结构**：`_boundsCache` / `_contentSizeCache` 为常量级，无随规模增长的重复分配。
- **视口裁剪收益**：绘制不再为离屏节点创建/持有中间对象，长会话下 GC 压力显著降低。

> 真机精确内存（Canvas 像素缓冲、DOM 气泡等）需在微信开发者工具性能面板实测；本报告给出的是算法层面的内存增长趋势结论：**由 O(n) 每帧扫描转为视口内常量级处理，内存随规模的额外增长被限制在布局/索引本身的一次性成本内。**

### 3.5 交互响应时间（推导）

| 交互 | 优化前 | 优化后 |
| --- | --- | --- |
| 平移/缩放一帧 | O(n) 重算边界 + 2 次全量遍历 | O(1) 缓存 + O(可见节点) |
| 点击命中检测 | O(n) 全量遍历 | O(可见节点 + log n) |
| 搜索定位 | 手动查找 | 命中后自动居中高亮 |

在 1000 人规模下，点击命中检测的遍历量从 1000 次降至视口代际内个位数~数十次，响应时间从「可能可感知的数十 ms 级」降至「个位数 ms 级」。

## 四、结论

1. **性能**：通过内容尺寸缓存 + 空间索引视口裁剪，单帧遍历量在 100~5000 人规模下稳定下降约 89%~92%，千人大族的平移/缩放与点击命中从全量扫描变为视口内处理。
2. **「找不到树」**：通过「定位到我」、搜索命中自动居中高亮、代数窗口加载与操作指引，用户可快速定位并导航到目标成员。
3. **体验**：新增加载状态、空态、错误重试与人数提示，消除「空白树」的困惑。

优化在保持完整家族关系展示的前提下，将大族渲染从「线性随全量成员增长」收敛为「随视口内可见成员增长」，达到了本次优化的目标。
