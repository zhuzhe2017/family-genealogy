# 家谱树绘制性能优化方案

> 适用范围：微信小程序「家谱树」页面（`mini-program/pages/family-tree-detail`）
> 目标：解决家族成员数量较多（数百至上千人）时，家谱树无法正常显示或「找不到树」的问题。

## 一、背景与问题

家谱树使用原生 Canvas（`type="2d"`）绘制树体，并通过 DOM 覆盖层展示成员详情气泡（混合方案）。在成员规模增大后出现两类典型问题：

1. **性能问题**：平移/缩放卡顿，首次渲染耗时上升，点击命中检测变慢。
2. **「找不到树」问题**：宽树（横向跨度大）被整体缩到屏幕内后，卡片尺寸低于可读阈值，只能看到色块而无法辨识，用户不知道该从哪里看起、如何定位某人。

## 二、根因分析

### 2.1 性能瓶颈

| 环节 | 原实现 | 复杂度 | 问题 |
| --- | --- | --- | --- |
| 内容边界计算 `getBounds` | 每帧对全部 layout 做 O(n) 扫描 | O(n)/帧 | 平移、缩放、命中检测每次都要重算 |
| 连线绘制 | 每帧全量遍历 `renderNodes` | O(n)/帧 | 大量离屏节点仍被计算 |
| 节点绘制 | 每帧全量遍历 `renderNodes` | O(n)/帧 | 同上，重复两次遍历 |
| 命中检测 `hitTest` | 每次点击全量遍历 `renderNodes` | O(n)/次 | 大族点击卡顿明显 |

当 n = 1000 时，单帧仅遍历就达到约 3000 次（连线 + 节点 + 边界），命中检测再加 1000 次；5000 人时单帧遍历约 15000 次，成为主要瓶颈。

### 2.2 「找不到树」的原因

1. **超大宽树初始缩放过度**：`computeFitScale` 为保证整棵树落屏，把横向跨度很大的树缩到很小，卡片屏幕宽度低于 LOD 中间阈值（< 90px），只渲染为色块，失去可读性。
2. **缺少定位入口**：无「定位到我」、无搜索命中后的自动居中，用户只能手动拖拽寻找。
3. **无加载/错误反馈**：加载失败时静默回退或空白，用户无法判断是「没有数据」还是「加载失败」。

## 三、优化方案设计

共实现 5 项优化，覆盖性能、可用性与体验三个层面：

### 方案 1：内容尺寸缓存（消除每帧 O(n) 重算）

- 新增 `_boundsCache` / `_contentSizeCache`，`getBounds` / `getContentSize` 首次计算后缓存。
- 布局或画布尺寸变化时通过 `invalidateLayoutCache()` 统一失效。
- 效果：平移/缩放帧中，内容尺寸从 O(n) 降为 O(1)。

### 方案 2：空间索引 + 视口裁剪（视图区域动态渲染）

- 新增 `buildSpatialIndex()`：按「代际（generation）」分层，代内按 x 坐标升序排序。
- 新增 `forEachVisibleLayout()`：由视口 y 范围反推代际区间，代内用二分查找定位到视口左边界，遍历到右边界即提前 break。
- 绘制连线与节点、命中检测全部改为走该方法，只处理可见代际与可见 x 区间内的节点。
- 效果：每帧遍历从 O(n) 降为 O(可见节点 + log n)，且只绘制进入视口的内容。

### 方案 3：层级折叠/展开 + 代数窗口加载（数据分页加载）

- **折叠/展开**：保留原有 `toggleCollapse`，点击节点折叠指示器可隐藏/显示其后代分支，减少同屏渲染量。
- **代数窗口**：顶部提供「默认 / 5代 / 7代 / 全部」四档，按需请求后端（`generations` 参数），并用 `_genCache` 缓存窗口结果，避免重复请求。
- 效果：大族默认只加载/渲染 3 代，用户需要时再逐级扩大，兼顾数据量与关系完整性。

### 方案 4：人员查找 / 定位 / 导航

- `locateMe()`：一键定位当前用户绑定成员；若在直系图则先切回树状图；若当前窗口未加载该成员，则切到「全部」并通过 `_pendingLocateId` 待定位。
- `locateMember(id)` / `centerOn(layout)`：高亮目标节点并平移/缩放使其居中，且保证放大到可读细节等级（≥ 90px）。
- `locateFirstMatch(kw)`：搜索命中后自动居中高亮首个命中成员。
- `clearHighlight()`：清空高亮。
- 效果：直接解决「找不到树 / 找不到人」的核心痛点。

### 方案 5：加载状态、错误处理与操作指引

- 新增 `loading / empty / loadError / memberCount` 状态。
- `loadTreeData` 成功/失败分别设置状态；失败且非 mock 时展示 `loadError`，并提供「重新加载」（`retryLoad`）。
- 底部提示显示「共 N 人 · 拖动平移 · 双指缩放 · 点击成员查看详情」。
- 空态提示引导「添加成员」。
- 效果：用户始终能感知加载进度与失败原因，降低「空白树」造成的困惑。

## 四、实现要点（关键代码位置）

核心逻辑集中在 `mini-program/pages/family-tree-detail/family-tree-detail.js`：

| 方法/字段 | 作用 |
| --- | --- |
| `_boundsCache` / `_contentSizeCache` | 内容尺寸缓存 |
| `_genIndex` | 空间索引（代际分层 + x 升序） |
| `_pendingLocateId` / `_pendingCenterLayout` | 待定位成员 / 画布未就绪时暂存居中布局 |
| `invalidateLayoutCache()` | 缓存失效 |
| `buildSpatialIndex()` | 构建空间索引 |
| `visibleGenRange()` | 由 y 范围反推代际区间 |
| `forEachVisibleLayout()` | 视口内节点遍历（分层 + 二分） |
| `drawTreeContent()` | 连线/节点绘制改为视口裁剪 |
| `getBounds()` / `getContentSize()` | 边界/尺寸缓存 |
| `hitTest()` | 命中检测改用空间索引 |
| `locateMe()` / `locateMember()` / `centerOn()` / `locateFirstMatch()` / `clearHighlight()` | 定位/导航/高亮 |
| `retryLoad()` | 失败重试 |

对应 WXML/WXSS 增加了「全部」代数选项、「定位」按钮、空态/错误态提示与样式。

## 五、性能测试标准

- 数据量级：100 / 500 / 1000 / 2000 / 5000 人。
- 指标：树构建耗时、布局耗时、空间索引构建耗时、单帧遍历次数（优化前 vs 优化后）。
- 内存与交互响应时间基于遍历复杂度推导，具体数据见《家谱树性能测试报告》。

## 六、遗留与后续建议

1. `hitCollapseToggle` 仍对 `renderNodes` 全量遍历（仅遍历有子节点者），在超大族下可进一步改用空间索引。
2. 内存占用指标建议在真机通过微信开发者工具「性能/内存」面板实测，本方案提供的是计算复杂度层面的推导值。
3. 可在后端对「全部」窗口增加字段裁剪，进一步降低大族一次返回的载荷。
