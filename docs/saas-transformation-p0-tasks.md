## 2. 任务详情

### T1 租户显式化与数据字典（P0 地基）

- **目标**：将 `family` 提升为显式租户实体，明确租户边界，输出全量数据字典。
- **关键步骤**：
  1. 盘点所有含 `family_id` 的业务表（member/document/photo/event/dynamic/backup/subscription/quota/permission 等），形成归属关系清单；
  2. 评估"新增 `tenant_id` 冗余字段" vs "沿用 `family_id` 作为租户键"两种方案的利弊，输出选型结论；
  3. 定义租户模型扩展字段（状态、来源、等级、套餐模板、配额模板）；
  4. 输出《租户数据字典 v1》。
- **交付物**：《租户数据字典》《family_id 归属清单》《tenant_id 选型结论》。
- **负责人**：BE（PM 参与评审）。
- **验收标准**：所有业务表归属关系可查可追溯；选型结论有明确建议与理由。

### T2 租户隔离基线审计

- **目标**：确保所有租户级数据访问都经过归属校验，越权风险清单归零。
- **关键步骤**：
  1. 审计 portal / family / family-member / subscription 等模块的 SQL，逐条确认是否携带 family_id 且经过 `family_permission` 校验；
  2. 输出《越权风险清单》（高危/中危/低危三级）；
  3. 对每项风险给出修复建议（归属校验补齐 / 参数校验 / 索引补充）；
  4. 形成隔离基线基线文档，供后续实施阶段直接领用。
- **交付物**：《租户隔离基线审计报告》。
- **负责人**：BE（安全评审 OPS 参与）。
- **验收标准**：高危风险 0 项；中低危均有修复方案与负责人。

### T3 租户生命周期与配额模板

- **目标**：定义租户全生命周期状态机与配额发放规则。
- **关键步骤**：
  1. 设计租户状态机：注册（创建家族）→ 待审核 → 正常 → 冻结 → 注销/归档；
  2. 定义各状态下的能力范围（可操作功能、数据可见性）；
  3. 设计租户级配额模板（存储、成员、订阅档位的默认配置）；
  4. 输出《租户生命周期规范》。
- **交付物**：《租户生命周期规范》《配额模板定义》。
- **负责人**：PM 主笔，BE 评审技术可行性。
- **验收标准**：状态机覆盖注册→注销全链路；配额模板可指导 T7 套餐模板实现。

### T4 租户上下文与统一 Guard 设计

- **目标**：统一租户级请求的上下文注入、传播与校验标准。
- **关键步骤**：
  1. 梳理现有 `UserJwtAuthGuard` / `EntitlementGuard` / 家族归属校验的调用模式；
  2. 设计租户上下文（TenantContext）的注入/传播/失效规则；
  3. 设计统一租户 Guard（认证 → 归属校验 → 能力点校验三层串联）的接口形态；
  4. 输出《租户上下文与 Guard 设计》。
- **交付物**：《租户上下文规范》《统一 Guard 设计》。
- **负责人**：BE。
- **验收标准**：所有租户接口的校验链路由设计文档完整覆盖，无遗漏分支。

### T5 平台管理员分级

- **目标**：区分全局管理员与家族关联管理员，落实最小权限。
- **关键步骤**：
  1. 明确两级管理员职责边界（全局：平台运营/配置/审计；关联：仅管辖指定家族）；
  2. 复用现有 `sys_admin_family` 关联模型，设计数据范围控制规则；
  3. 梳理平台权限码清单，标注哪些仅全局、哪些可授予关联管理员；
  4. 输出《平台管理员分级方案》。
- **交付物**：《平台管理员分级方案》。
- **负责人**：BE 主笔，FE（web-admin）评审菜单/权限展示影响。
- **验收标准**：权限码与数据范围映射表完整；无"全局可见所有家族业务数据"的默认行为。

### T6 数据分级与脱敏方案

- **目标**：建立数据分级清单与默认最小可见的展示规则。
- **关键步骤**：
  1. 对全量数据项分级：公开（姓氏文化）/ 家族内（谱系成员）/ 私密（联系方式、证件、死者细节）；
  2. 定义各级展示/脱敏规则（如手机号中间位隐藏、证件号部分展示）；
  3. 明确死者信息展示策略（姓名/生卒年可示，隐私细节需成员同意）；
  4. 输出《数据分级与脱敏方案》，供实施阶段落地。
- **交付物**：《数据分级清单》《脱敏规则表》。
- **负责人**：PM + BE（LEGAL 合规把关）。
- **验收标准**：三级分类无争议；每条规则可映射到具体字段与接口。

### T7 能力点配置化与套餐模板化

- **目标**：盘点能力点硬编码点，设计套餐模板继承机制。
- **关键步骤**：
  1. 盘点代码中能力点（backup/export/permission/reminder/digest/theme/badge/ai_restore/worship_pro/print/advisor/support/no_ads）的硬编码位置；
  2. 设计能力点 + 参数结构（如 `{"export":{"format":["pdf","html"]}}`），评估对现有 `capabilities` JSON 的兼容性；
  3. 设计套餐模板机制（模板套餐 + 租户定制覆盖，`template_of` 字段）；
  4. 输出《能力点配置化清单》《套餐模板化设计》。
- **交付物**：《能力点硬编码盘点表》《套餐模板化设计》。
- **负责人**：BE。
- **验收标准**：所有能力点都有配置归属；模板继承规则可指导管理端"复制为变体"。

### T8 计费指标口径与埋点需求

- **目标**：统一商业化指标口径，定义埋点清单。
- **关键步骤**：
  1. 定义 MRR / ARR / 付费家族数 / Churn / ARPPU / LTV / CAC 的计算口径与数据来源；
  2. 对照现有 `subscription_order` / `family_subscription` 字段，指出缺口（如套餐变更历史、取消原因）；
  3. 输出埋点需求清单（事件、字段、上报时机）；
  4. 输出《商业化指标口径 v1》。
- **交付物**：《商业化指标口径》《埋点需求清单》。
- **负责人**：PM 主笔，BE 评审数据可行性。
- **验收标准**：每个指标有明确公式与数据来源表；埋点清单可交给 FE/BE 直接实施。

### T9 订阅生命周期补全

- **目标**：梳理试用期 / 自动续费 / 退款的状态机扩展点。
- **关键步骤**：
  1. 基于现有状态机（active/grace/frozen/expired）设计"试用期（trial）"状态与转换规则；
  2. 梳理 `auto_renew` 自动续费的流程（续费扣款时机、失败重试、通知）；
  3. 设计退款状态机（全额/部分、周期内保留、到期只读）与 `subscription_order` 字段扩展点；
  4. 输出《订阅生命周期扩展设计》。
- **交付物**：《订阅生命周期状态机扩展设计》。
- **负责人**：BE（PM 评审定价影响）。
- **验收标准**：每个新状态的进入/退出条件、触发方（用户/系统/管理端）、副作用均有定义。

### T10 存储外置（对象存储）评估

- **目标**：评估 `uploads/` 本地目录迁移对象存储（OSS/COS/S3）的可行性与成本。
- **关键步骤**：
  1. 盘点图片/文件上传路径、URL 生成与访问链路（含小程序 image 跨域、CDN）；
  2. 对比云厂商对象存储方案（选型、单价、CDN 加速、跨区域复制）；
  3. 设计字段兼容（URL 存储为完整可切换地址）与存量文件迁移方案；
  4. 输出《存储外置评估报告》。
- **交付物**：《存储外置评估报告》。
- **负责人**：BE + OPS。
- **验收标准**：报告含选型对比、成本估算、迁移步骤与回滚方案。

### T11 容器化与环境分离

- **目标**：实现 dev/test/prod 三环境可复现部署。
- **关键步骤**：
  1. 编写后端 Dockerfile（多阶段构建：依赖 → build → 运行）与前端 Dockerfile；
  2. 编写 docker-compose（本地一键起：MySQL + 后端 + 前端 + 可选 Redis）；
  3. 拆分 dev/test/prod 三套 env 模板（数据库、域名、CORS、支付配置隔离）；
  4. 输出《容器化与环境配置指南》。
- **交付物**：Dockerfile ×2、docker-compose.yml、env 模板 ×3、《部署指南》。
- **负责人**：OPS 主笔，BE 评审。
- **验收标准**：新环境按指南 30 分钟内可拉起；test 环境与生产同构。

### T12 基础监控与告警

- **目标**：接入 APM + 主机监控 + 核心业务告警。
- **关键步骤**：
  1. 选型并接入 APM（接口耗时/错误率/依赖调用链）；
  2. 配置主机监控（CPU/内存/磁盘/连接数）；
  3. 定义业务告警规则：支付失败率、订阅回调异常、备份失败、登录限流触发；
  4. 输出《监控告警配置清单》。
- **交付物**：《监控告警配置清单》《告警响应手册》。
- **负责人**：OPS（BE 提供业务指标点）。
- **验收标准**：三类监控全部在线；关键业务告警能在 5 分钟内触发通知。

### T13 备份与灾备

- **目标**：建立数据库/文件备份策略并完成首次恢复演练。
- **关键步骤**：
  1. 落地数据库每日全量（mysqldump/RDS 快照）+ binlog 增量归档；
  2. 明确备份异地存放（跨区域/跨云）与保留周期（全量 30 天、增量 7 天）；
  3. 执行首次恢复演练，记录 RPO/RTO 实测值（目标 RPO≤24h、RTO≤4h）；
  4. 输出《备份与灾备手册》。
- **交付物**：《备份策略》《恢复演练报告》。
- **负责人**：OPS。
- **验收标准**：备份任务连续运行 7 天无失败；演练恢复出可验证数据。

### T14 隐私政策与同意流程

- **目标**：编写隐私政策/用户协议/成员告知文本，设计同意流程。
- **关键步骤**：
  1. 由 LEGAL 起草《隐私政策》《用户协议》《成员信息告知》（含数据用途、期限、删除权）；
  2. 设计小程序端同意流程（首次进入弹窗、家族成员入族告知）、管理端下载入口；
  3. 结合 T6 脱敏规则核对文本与实现一致性；
  4. 输出《合规文本 v1》《同意流程设计》。
- **交付物**：合规文本 ×3、同意流程设计。
- **负责人**：PM + LEGAL + FE。
- **验收标准**：文本通过法律审查；同意流程满足"告知-同意"并可留存记录。

## 6. 与后续阶段的衔接

- 本清单全部为**规划/基线产出**，直接作为阶段二（P1）与实施阶段的需求输入；
- T2 的风险修复清单、T6 的脱敏规则、T7 的配置化设计、T9 的状态机扩展，是后续代码改造的**直接任务来源**；
- 收口时建议为每项交付物建立文档索引，纳入 `docs/` 统一管理。
